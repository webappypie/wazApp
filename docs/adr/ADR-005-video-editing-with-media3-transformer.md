# ADR-005 — Video editing on Android with Media3 Transformer; no iOS editor yet

- **Status:** accepted (Phase 3). Android: implemented, verified on an Android 16 **emulator** (see RELEASE_EVIDENCE) — not yet on a physical phone. iOS: **not implemented** (blocked-by-environment: no Xcode/macOS).
- **Context:** The PRD wants trim, mute, crop and text overlays "only where supported", real progress/cancel, output validation, and no fake controls. FFmpeg Flutter plugins are discontinued/retired; hand-rolled MediaCodec/OpenGL pipelines are error-prone.
- **Decision:**
  - Use AndroidX **Media3 Transformer 1.9.2** (same media3 line as the `video_player_android` plugin, so one copy of the libraries is in the APK). Output is always **H.264 + AAC in MP4**, re-encoded (frame-accurate trim) with an explicit bitrate (~0.09 bits/pixel/frame at 30 fps, 1.5-20 Mbps).
  - Edits really performed natively: **trim** (`ClippingConfiguration`), **mute** (`setRemoveAudio`), **crop** (`Crop` effect in upright-frame coordinates), **output size** (`Presentation`, even width/height, cap 720p/1080p only when it shrinks the source, hard ceiling 3840 px), and **one full-frame transparent bitmap overlay** (`OverlayEffect`).
  - Text and stickers are rendered by **Dart** (same painter and bundled fonts as the photo editor and status maker) into a transparent PNG of exactly the output size, so Hindi shaping/fallback and positions match the on-screen preview; native code only composites the bitmap.
  - The bridge (`VideoExportHandler.kt`) reports progress (250 ms poll of `Transformer.getProgress`), supports `cancel` (stops the transformer and deletes partial output), refuses a second concurrent export, checks free space up front and maps codec failures to `unsupported`.
  - **Verification before the library accepts a file:** the exported file is described by the native `MediaMetadataRetriever` (size, duration, has-audio) and checked against the plan (`checkExportedVideo`: size ±2 px, duration ±max(500 ms, 5 %), muted ⇒ no audio, unmuted + source had audio ⇒ audio present), then `LibraryService.addCreatedFile` decodes it again through `video_player` and requires the same dimensions. Any failure/cancel removes temp output and adds no row.
  - Source is never modified; the result is a new "edited" item (`edited_<name>.mp4`).
- **Not offered:** rotate/flip (not wired for video), speed, filters/colour adjustments, free-form quality/bitrate, audio replacement, HDR tone-mapping choices, iOS editing (the Create tab and viewer simply do not show the video editor where `VideoEncoder.isSupported` is false).
- **Alternatives rejected:** FFmpeg kit (retired), raw MediaCodec+GL (maintenance/risk), AVFoundation without Xcode (unverifiable here), cloud transcoding (violates no-upload).
- **Consequences / limits:** encoding time on low-end phones is not measured; emulator software encoders differ from phone hardware encoders; HDR/10-bit and exotic codecs may fail with a clear "cannot be edited on this device" message.
- **Tests:** `video_edit_state_test` (trim clamp, sizes, plan, validation), `video_export_service_test` (fake encoder: mapping, overlay PNG, rollback on every failure, cancel), `video_editor_screen_test` (fake player + encoder), and `integration_test/video_export_test.dart` (real encoder on an emulator).
