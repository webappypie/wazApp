# ADR-002 — Android status discovery through the Storage Access Framework

- **Status:** accepted; **device validation partial** (see `docs/audit/RELEASE_EVIDENCE.md`)
- **Context:** WhatsApp stores statuses in a hidden `.Statuses` folder (`Android/media/<pkg>/WhatsApp[ Business]/Media/.Statuses` on Android 11+). MediaStore does not index it and a hard-coded path is not readable under scoped storage. `MANAGE_EXTERNAL_STORAGE`, hidden APIs and root are prohibited by the PRD and Play policy.
- **Decision:** The user picks the folder once with `ACTION_OPEN_DOCUMENT_TREE` (the picker opens on the expected folder via `EXTRA_INITIAL_URI`). The grant is persisted with `takePersistableUriPermission`. The native bridge (`StatusAccessHandler.kt`) validates that the chosen tree contains `.Statuses` (max depth 3) and that it belongs to the right app (WhatsApp vs WhatsApp Business are stored and validated separately), lists children with `DocumentsContract`, and copies files via `ContentResolver` to a `*.part` file, verifies byte count against the source size, renames atomically and decodes metadata; failures remove the partial output. All I/O runs on a background executor. No storage permission is declared.
- **Consequences:** works only after the user viewed a status in WhatsApp (WhatsApp creates the file then); OEM pickers differ — must be validated per device. Statuses expire after 24 h in WhatsApp; WazApp never deletes or modifies the originals.
- **Rejected:** MediaStore queries (statuses not indexed), direct `File` access (blocked on Android 11+), `MANAGE_EXTERNAL_STORAGE` (policy), accessibility/notification scraping (privacy/policy).
- **Tests:** `test/features/library/library_service_test.dart`, `test/features/status/home_screen_test.dart` (bridge faked); native bridge exercised on a physical device (see evidence).
